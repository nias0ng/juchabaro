고정 스타일 파일이 테마를 받게 하는 구조

원인은 StyleSheet.create로 한 번 만들어지는 스타일 파일이 테마 훅을 쓸 수 없다는 점이었다. 새 의존성 없이 스타일을 "토큰을 받는 함수"로 바꿨다.

원시 값
Palette

violet600 gray550 처럼 색상명 + 단계. 값을 직접 적는 유일한 곳.

→
용도 기반 토큰
ColorTokens

라이트 / 다크 두 벌. 모든 값이 팔레트 단계를 가리킨다. 대비 검사가 이 값을 직접 읽는다.

→
스타일 파일
createStyles(t)

파일 위치 규칙(*.styles.ts)은 그대로. 색 자리에 t.text.weak.

→
컴포넌트
useThemedStyles

(함수, 모드) 쌍마다 한 번만 만들어 재사용. 렌더마다 다시 만들지 않는다.

withAdaptiveColors(Screen) — 다크 모드는 화면 단위로 켠다. 공용 헤더·배경은 아직 옮기지 않은 화면에서도 쓰이는데, 그 화면들은 글자색이 라이트로 고정되어 있다. 공용 컴포넌트만 어두워지면 글자가 배경에 묻히므로, 화면이 통째로 옮겨졌다고 선언한 범위 안에서만 기기 모드를 따른다.
